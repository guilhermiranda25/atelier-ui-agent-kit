# Briefing e critérios de aceite

## Brief compacto
- Produto e resultado desejado (conversão, operação, inscrição, estudo, análise).
- Personas e dispositivos prioritários; idioma(s); restrições legais/regulatórias.
- Páginas, rotas, integrações, componentes já existentes e estados especiais.
- Marca existente (logo, tipografia, cores, tom, tokens) ou liberdade criativa.
- Exemplos de referência (o que inspirar e o que **não** copiar).
- Conteúdo real, origem dos dados, política de placeholder, fotos e assets.
- Requisitos técnicos: stack, SSR/CSR, segurança, WCAG, desempenho, CMS, analytics.
- Prazo e prioridades; nível de fidelidade; evidências para aceite.

## Critérios de aceite por dimensão
| Eixo | Aceite observável |
| --- | --- |
| Produto | Fluxos completos sem dead ends, conteúdo correto |
| Visual | Hierarquia clara, identidade própria, consistência cross-page |
| UX | Estados loading/empty/error/success e respostas compreensíveis |
| Responsivo | Nenhum corte/overflow, pontos de quebra testados |
| Acessibilidade | Foco, teclado, labels, contraste, reduced motion |
| Frontend | Tipagem, import hygiene, componentização, testes |
| Performance | Sem efeito caro bloqueando leitura/interação, perfis verificados |
| Legal | Fontes/imagens/componentes com permissões confirmadas |

## Entrega para revisão
Fornecer uma tabela: tela / alteração / evidência / resultado / riscos. Apontar explicitamente itens não testados. Não prometer 100% de eficácia sem validação no ambiente de produção.
